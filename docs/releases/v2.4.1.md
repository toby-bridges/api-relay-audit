# v2.4.1: DSH compatibility and curl credential handling

API Relay Audit v2.4.1 is a patch release for the DeepSeek Harness bundle and
the local curl fallback. It keeps the 14-step audit, CLI profiles, report
schema, and 6D risk matrix unchanged.

## What Changed

- [#104](https://github.com/toby-bridges/api-relay-audit/pull/104) supports the
  exact tested DSH `0.1.0-rc.6`, `0.1.7-rc.2`, and `0.2.0-rc.2` peer versions.
  Newer hosts use redacted settings descriptors to resolve the current route.
- Error probes and streaming curl fallback pass credential headers through
  curl config stdin instead of process arguments. The request body is held in
  a private, short-lived file. Both modular and standalone distributions carry
  the change.
- `/relay-audit --help` states the current Claude-route requirement and the
  metered cost of a full audit. Documentation distinguishes this release from
  the immutable `v2.4.0` artifact.

## Quick Start

```bash
AUDIT_SCRIPT_REF=v2.4.1
curl -fsSL "https://raw.githubusercontent.com/toby-bridges/api-relay-audit/${AUDIT_SCRIPT_REF}/audit.py" -o audit.py
python3 audit.py --key <YOUR_KEY> --url <BASE_URL> --output report.md
```

Install the DSH bundle into an isolated profile first:

```bash
dsh plugin --profile web add "github:toby-bridges/api-relay-audit#v2.4.1"
```

The DSH command currently accepts routes declaring a Claude model. This
release does not add a DeepSeek or Codex model baseline.

- Isolated rc.17 and rc.20 Web profiles installed and booted with the exact

  connectivity checks without exposing the fake key in process arguments or
  the report.

- The tagged `audit.py`, generated standalone output, release asset, and
  published SHA-256 file must be byte-identical before publication.
- Published release checks: `/releases/latest` and `/releases/tags/v2.4.1`.

## Limits

- Interactive Web command submission and Desktop profiles remain unverified;
  the newer-host connectivity proof used an installed command handler. Full
  14-step relay behavior still depends on the relay under test.
- API Relay Audit does not certify that a relay is safe. Keep API keys, private
  relay URLs, headers, raw responses, and user data out of public reports.
