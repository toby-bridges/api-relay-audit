How to audit a Claude API relay safely

To audit a Claude-compatible relay safely, run the audit locally, point it only at the relay URL you intend to test, and review each finding as evidence rather than as a safety certificate.

Safe audit checklist

  1. Use a scoped API key with limited budget when possible.
  2. Run the standalone `audit.py` locally so the key does not pass through a separate web checker.
  3. Save the Markdown report and review red, yellow, and inconclusive items.
  4. Do not publish real relay credentials, private domains, wallet addresses tied to private use, or raw traffic captures.

Command

curl -sO https://raw.githubusercontent.com/toby-bridges/api-relay-audit/master/audit.py
python audit.py \
  --key <YOUR_KEY> \
  --url <BASE_URL> \
  --model claude-opus-4-6 \
  --output claude-relay-audit.md

Interpreting inconclusive results

Inconclusive means the probe could not establish a clean or anomalous result. It may happen because the relay blocks a request, does not support a format, truncates an answer, or returns an ambiguous response. Do not treat inconclusive as clean.

Interpretation guide: signals, checks, and limits

This is an interpretation guide, not a detection-accuracy benchmark or a set of real-provider case studies. These signals call for review; none alone certifies a relay as safe or malicious.

Observed signalHow to cross-checkWhat it does not establish
Input tokens substantially exceed the estimate. Match the model, messages, system/tool configuration, and token-counting rules. Repeat the probe; where available, compare the same request against an authorized official endpoint. A token delta alone does not prove malicious prompt injection. The current probe uses approximate fixed baselines, not a matched official-endpoint measurement.
The response claims a different model identity. Check for role-play or identity instructions. Repeat with neutral prompts, then compare response metadata with independently verifiable upstream evidence. Keep private captures local. Self-identification or a relay-supplied model field alone does not prove model substitution or identify the actual upstream provider.
An Anthropic-style SSE stream lacks message_stop. Confirm the expected protocol and inspect the full event sequence, timeouts, client cancellation, and proxy disconnects. Transport errors or no substantive events remain inconclusive. An incomplete stream does not by itself prove tampering or model downgrade. Do not apply Anthropic event requirements to OpenAI-only streams; a clean stream is not a safety certificate.

Report wording caveat: v2.4.0 token reports can label a delta as detected injection. Treat that label as a heuristic finding requiring the cross-checks above, not confirmation of its cause.

Related classifier limitation: the public synthetic reproduction in issue #79 documents a separate prompt-extraction false positive on a pinned version. It supports manual review, not a measured error rate or a finding about any provider.
